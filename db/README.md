# База данных проекта

Локальный PostgreSQL 17 (установлен на этом компьютере, служба Windows
`postgresql-x64-17`, порт 5432). Схема покрывает только то, что реально
использует сайт: портфолио проектов, их фото, заявки с формы и отзывы.

## Файлы

- `schema.sql` — создаёт 4 таблицы: `projects`, `project_photos`, `leads`, `reviews`.
- `seed.sql` — тестовые данные: реальные проекты портфолио и реальные пути к
  фото из `public/projects`, плюс полностью вымышленные заявки и отзывы.
- `postgresql.conf.localhost.md` — какую строку поменять в конфиге PostgreSQL,
  чтобы сервер был доступен только с этого компьютера (`listen_addresses = 'localhost'`).

## Как создать базу и применить схему

Используется `psql` из установки PostgreSQL 17
(`C:\Program Files\PostgreSQL\17\bin\psql.exe`). При подключении `psql`
запросит пароль пользователя `postgres`, заданный при установке.

1. Создать базу данных (имя `design_portfolio`):

   ```
   "C:\Program Files\PostgreSQL\17\bin\createdb.exe" -U postgres design_portfolio
   ```

2. Применить схему:

   ```
   "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -d design_portfolio -f db\schema.sql
   ```

3. Проверить, что таблицы создались:

   ```
   "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -d design_portfolio -c "\dt"
   ```

Скрипт `schema.sql` рассчитан на пустую базу и запускается один раз
(без `IF NOT EXISTS` — если что-то пошло не так, безопаснее увидеть ошибку,
чем молча пропустить создание таблицы).

## Структура

```
projects (1) ──< (N) project_photos   -- по project_photos.project_id
leads      -- отдельно, без связей с другими таблицами
reviews    -- отдельно, без связей с другими таблицами
```

## Почему такие ограничения и индексы

- `projects.slug UNIQUE` — по нему идёт открытие карточки проекта на сайте
  (`/projects/<slug>`), дубликаты недопустимы. UNIQUE заодно создаёт индекс
  под этот поиск — отдельный индекс не нужен.
- `project_photos.project_id` со ссылкой `REFERENCES projects(id) ON DELETE CASCADE` —
  при удалении проекта его фото удаляются автоматически, не остаются "сиротами".
- `UNIQUE (project_id, sort_order)` в `project_photos` — не даёт двум фото
  одного проекта получить одинаковый порядковый номер; как побочный эффект
  даёт индекс, по которому быстро достаются все фото одного проекта
  (это единственный реальный запрос к этой таблице на сайте).
- Отдельных индексов для `leads` и `reviews` не добавлено — сайт всегда
  читает эти таблицы целиком (все заявки / все отзывы), а не по каким-то
  условиям поиска, и объём данных (десятки-сотни строк) не требует
  дополнительной оптимизации.
- `NOT NULL` расставлен только там, где поле обязательно и в текущей форме
  сайта, и по смыслу: `leads.name`, `leads.contact` (форма требует их через
  `required`), `projects.description`/`title`/`cover_url` (всегда заполняются
  для показа на сайте). Необязательные в форме/данных поля (`area`,
  `location`, `year`, `style`, `message`, `project_type` и т.д.) оставлены
  nullable — у части существующих проектов портфолио они и сейчас пустые.
- `CHECK` на `type`/`project_type` — ограничивает значения тем набором,
  который реально показывает интерфейс (квартира/дом, плюс «другое» для заявок).
