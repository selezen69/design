# Design System — редизайн сайта-портфолио

Дополняет `product.md`. Описывает конкретные значения: цвета, шрифты, сетку,
отступы, кнопки, карточки, фотографии, навигацию и адаптацию. Base-палитра и
шрифтовые семейства текущего сайта (`src/index.css`) сохраняются — меняется
не палитра, а пропорции и масштаб использования.

## 1. Принцип

Фотография — главный герой; текст и интерфейс — тихие. Асимметричная
редакционная сетка вместо симметричного центрирования: текстовый блок сдвинут
к краю, фотография — full-bleed (во всю ширину вьюпорта, без контейнера).
Одно крупное исключение — Hero, который остаётся кинематографично
полноэкранным.

## 2. Цвета

Токены не меняются (оставить как есть в `@theme`):

| Токен | Hex | Использование |
|---|---|---|
| `--color-graphite` | `#1a1a1a` | тёмные сцены, текст на светлом |
| `--color-charcoal` | `#2d2d2d` | hover тёмных заливок |
| `--color-stone` | `#6b6b6b` | вторичный текст на светлом |
| `--color-silver` | `#c4c4c4` | третичный текст **только на тёмном фоне** |
| `--color-fog` | `#f0efed` | нейтральный светлый фон |
| `--color-beige` | `#e8e0d5` | акцентный светлый фон (Что ценят наши клиенты) |
| `--color-cream` | `#faf8f5` | базовый светлый фон |
| `--color-accent` | `#c9a96e` | акценты, эйбраузеры, hover-состояния |

**Правило контраста:** `silver` больше не используется на `cream`/`white`/
`fog` (сейчас нарушено в лейблах модалки проекта и в тексте про политику
конфиденциальности — контраст ~1.8:1). На светлом фоне вторичный текст —
только `stone` (контраст ≥ 4.6:1). `silver` остаётся допустимым исключительно
на `graphite`/`charcoal` при непрозрачности не ниже 70% для основного текста
(decorative-элементы вроде крупных номеров этапов — можно ниже).

**Ритм тёмных/светлых сцен.** Сейчас 2 тёмных блока (Hero, Этапы) на 7
секций. Новое правило: чередование происходит на каждой смысловой границе —
минимум 3 тёмных «сцены» на десктопном скролле главной (Hero → светлая пауза
→ тёмная вставка между Портфолио и О дизайнере или внутри Услуг/Этапов →
светлый блок Контактов в конце, как «выдох»).

## 3. Шрифты

Семейства без изменений: `--font-serif: "Cormorant Garamond"`, `--font-sans:
"Inter"`. Меняется **частота и масштаб** serif: раньше — в каждом h2/h3
секции; теперь — только в двух местах: заголовок Hero и заголовок открытого
проекта. Все h2 секций переезжают на `--font-sans`.

| Элемент | Шрифт | Размер (mobile → desktop) | Вес | Трекинг |
|---|---|---|---|---|
| Hero H1 | serif | `clamp(2.75rem, 10vw, 8rem)` | 300 | 0 |
| Заголовок проекта (открытая страница) | serif | `clamp(2.25rem, 6vw, 4.5rem)` | 300 | 0 |
| H2 секции | sans | `clamp(1.5rem, 3.2vw, 2.25rem)` | 500 | `0.01em` |
| H3 карточки/подраздела | sans | `1.125rem–1.25rem` | 500 | `0.01em` |
| Эйбраузер (label над заголовком) | sans | `0.75rem` | 500 | `0.4em`, uppercase |
| Основной текст | sans | `1rem–1.125rem` | 400 | 0 |
| Мелкий текст/мета | sans | `0.75rem–0.8125rem` | 500 | `0.15em`, uppercase |

## 4. Сетка

12-колоночная сетка, `max-width: 1600px` для контейнеров с текстом,
**без max-width** для full-bleed фото (растягивать на 100vw секции).

- Gutter: `24px` mobile, `32px` tablet, `40px` desktop.
- Асимметрия: текстовый блок секции занимает колонки 1–5 (из 12) на
  desktop, сдвинут к левому краю, а не центрирован; фото/иллюстрация занимает
  оставшиеся 6–12 колонки или уходит full-bleed за пределы контейнера.
- Портфолио-грид: 2 колонки на desktop, но карточки разной "высоты"
  (чередование альбомных 3:2 и портретных 2:3 исходников без принудительного
  кропа в 4:3) — сетка masonry-подобная, не строгая решётка.
- Брейкпоинты: `sm: 480px`, `md: 768px`, `lg: 1024px`, `xl: 1440px` (совпадают
  с Tailwind default, менять не нужно).

## 5. Отступы

Вертикальный ритм между секциями — переменный, три уровня «паузы»:

| Уровень | Значение (mobile → desktop) | Когда |
|---|---|---|
| Короткая | `64px → 96px` | внутри одной смысловой темы (Услуги → Этапы) |
| Средняя | `96px → 160px` | между разными темами (Портфолио → О дизайнере) |
| Длинная | `140px → 260px` | после Hero и перед Контактами — акцентная пауза |

Горизонтальные отступы контейнера с текстом: `24px` mobile, `48px` tablet,
`80px` desktop (шире текущих `px-6`, т.к. текст теперь не на всю ширину).

## 6. Кнопки

Без изменений в базовой геометрии (без скруглений, uppercase, tracking
`0.1em–0.15em`), унифицировать hover:

- **Primary** (`bg-accent` / `bg-graphite`): при hover — заливка темнеет
  (`charcoal`/`accent/90`), без изменения размера.
- **Secondary** (обводка): при hover обводка не меняет цвет мгновенно —
  снизу слева направо "заливается" линия-подложка `2px` высотой на `accent`,
  за `300ms ease-out`, текст остаётся читаемым поверх.
- Все интерактивные текстовые ссылки (нав, "Смотреть проект") получают тот же
  paттерн: `underline` шириной 0 → 100% слева направо при hover/focus,
  `200ms ease-out`, `text-underline-offset: 4px`.

## 7. Карточки

Два варианта, не один:

1. **Hero-карточка** (первый/самый крупный проект в сетке портфолио) — текст
   (название + категория) лежит поверх фото на градиенте снизу
   (`bg-gradient-to-t from-graphite/80 to-transparent`), занимает всю ширину
   отведённых колонок.
2. **Стандартная карточка** (остальные проекты) — как сейчас: фото сверху,
   название/категория под фото, но **без** принудительного `aspect-[4/3]` —
   каждая карточка сохраняет исходную пропорцию фото (в пределах `min-height`
   ограничения, чтобы не ломать сетку).

Обе — `cursor-pointer`, `role="button"`, `tabIndex={0}`, `onKeyDown` (Enter/
Space) — сохранить текущую доступность без изменений.

> **Для первого прототипа:** открытие проекта остаётся текущей модалкой
> (`ProjectDetail`, без отдельного маршрута/URL) — меняется только раскладка
> содержимого внутри неё (см. §8, редакционная галерея). Существующая
> доступность модалки (`role="dialog"`, `aria-modal`, `Escape`, focus trap)
> переносится как есть.

## 8. Фотографии

- Не резать всё в `aspect-[4/3]`. Разрешённые пропорции в сетке: `3:2`,
  `2:3`, `1:1` — выбираются по факту исходника, не подгоняются искусственно.
  Full-bleed секции (Hero, обложка проекта) — `object-fit: cover` с фиксом
  через `aspect-[16/9]` mobile / `aspect-[21/9]` desktop, как сейчас в
  `ProjectDetail`.
- **Адаптивное правило вместо единого лимита в KB.** Формальный потолок веса
  на файл не годится — вес должен зависеть от того, где и как крупно фото
  показывается, а не быть одним числом для всех случаев:
  - **Hero / обложка проекта (LCP-кандидат):** загружается приоритетно
    (`fetchpriority="high"`, без `loading="lazy"`, предзагрузка через
    `<link rel="preload" as="image">` при необходимости) — это то фото,
    которое определяет метрику LCP, задержка недопустима.
  - **Превью в сетке портфолио:** свои, более компактные размеры под
    реальную ширину карточки, не полноразмерный оригинал, уменьшенный CSS.
  - **Галерея открытого проекта:** размеры под фактическую ширину слота в
    редакционной раскладке (крупный full-bleed слот и средний слот — это
    два разных набора размеров, не один универсальный).
  - Для каждого случая — `srcset`/`sizes` (или `<picture>`) с несколькими
    реальными размерами файла, браузер сам выбирает подходящий; форматы —
    **AVIF/WebP как основные, JPEG как fallback**.
  - Все фото, кроме приоритетного LCP-изображения, — `loading="lazy"`
    (уже есть в галерее проекта — распространить на портфолио-грид).
  - Ориентир по весу — по ситуации (превью заметно легче полноэкранного
    Hero-кадра), но это следствие правильного размера и формата, а не
    самоцель: **визуальное качество не приносится в жертву ради того, чтобы
    формально уложиться в цифру**. Итоговый вес проверяется на глаз и через
    Lighthouse/WebPageTest, а не через жёсткий чек-лист "≤ N KB".
- `width`/`height` или `aspect-ratio` в CSS всегда заданы явно — не допускать
  сдвига layout (CLS) при догрузке изображений.

## 9. Навигация

- **Desktop:** логотип + «Портфолио» + «Услуги» + «Контакты» — всегда
  видимые, не прячутся в меню. Остальные пункты (О дизайнере, Процесс, Что
  ценят наши клиенты) — в компактной раскрывающейся панели (не полноэкранный
  оверлей):
  панель шириной `360px`, выезжает справа, фон `graphite`, текст `cream`,
  список без вложенных подменю (плоский, в одну колонку). Открытие/закрытие —
  по клику на "Меню" (текст, не только иконка, чтобы не терять
  discoverability, в отличие от полностью скрытой навигации ysg.studio).
- **Mobile:** компактное меню — видны логотип и точка входа в меню (бургер/
  «Меню»), список ссылок (включая «Услуги») открывается по клику, панель
  на `100%` ширины экрана. Постоянно держать 3 ссылки на узком экране не
  нужно — здесь плотность важнее, чем на desktop.

## 10. Адаптация

- До `768px` (mobile): асимметричная сетка **схлопывается** в одну колонку;
  текстовый блок идёт первым или вторым в зависимости от смысла (не всегда
  «текст сверху»), фото остаётся full-bleed по ширине экрана.
  Hero — полноэкранный (`100dvh`, не `100vh`, чтобы не резать мобильные
  тулбары).
- Touch-таргеты — не меньше `44×44px` (кнопки, пункты меню, стрелки
  галереи).
- Портфолио-фильтр (Все/Квартиры/Дома) на mobile — горизонтальный скролл
  вместо переноса строк, если не помещается.

## 11. Производительность

- Изображения — см. §8 (адаптивные размеры/форматы/приоритет вместо жёсткого
  лимита в KB); цель по метрикам, а не по формальному весу файла: LCP не
  хуже текущего показателя сайта, без регрессии при внедрении новой
  редакционной раскладки.
- Шрифты — `font-display: swap`, подключать только используемые начертания
  (сейчас Cormorant Garamond 300/400/500 italic + Inter 300/400/500 — не
  расширять список без необходимости).
- Не использовать библиотеки для parallax/reveal там, где хватает
  `IntersectionObserver` + CSS `transform`/`opacity` (см. `motion-spec.md`) —
  меньше JS на клиенте.

## 12. Доступность

- Контраст текста — не ниже 4.5:1 для обычного текста, 3:1 для крупного
  (≥24px) — проверять новые сочетания цвет/фон перед внедрением.
- Все поля форм — `label` со связкой `htmlFor`/`id` (текущий пробел в
  `Contact.jsx`, чинится отдельно от редизайна, но новая форма не должна
  повторить ошибку).
- Модальные окна/панель меню — `role="dialog"`, `aria-modal`, `Escape`,
  focus trap — по образцу уже корректно сделанного `ProjectDetail.jsx`.
- Все интерактивные `div` — только с `role`, `tabIndex`, `onKeyDown`, как
  сейчас в `ProjectCard`.
