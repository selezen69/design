# Motion Spec — редизайн сайта-портфолио

Дополняет `product.md` и `design-system.md`. Все значения — отправная точка
для реализации, не финальный код. Технически: CSS `transition`/`@keyframes`
+ `IntersectionObserver` там, где нужен триггер по скроллу. Без сторонних
анимационных библиотек, без скролл-джекинга, без 3D-трансформаций.

## 1. Принципы

- Каждая анимация обслуживает восприятие (направляет внимание, обозначает
  переход) — декоративных эффектов «ради эффекта» нет.
- Анимируются только `transform` и `opacity` (не `top`/`margin`/`width`) —
  чтобы не проседала производительность и не было layout thrashing.
- Никакого скролл-джекинга (перехвата нативного скролла) — скролл всегда
  остаётся родным браузерным.
- Никакого автовоспроизведения звука — нигде.
- `prefers-reduced-motion: reduce` обязателен везде, где есть смещение,
  масштабирование или параллакс (раздел 8).

## 2. Reveal-on-scroll (появление блоков)

Механизм: один `IntersectionObserver` с `threshold: 0.2`, `rootMargin:
"0px 0px -10% 0px"` — класс добавляется один раз при первом пересечении
(`unobserve` после срабатывания, повторно не проигрывать при обратном
скролле).

| Параметр | Значение |
|---|---|
| Начальное состояние | `opacity: 0; transform: translateY(24px)` |
| Конечное состояние | `opacity: 1; transform: translateY(0)` |
| Длительность | `800ms` |
| Easing | `cubic-bezier(0.16, 1, 0.3, 1)` (ease-out, без пружины) |
| Задержка между соседними элементами (stagger) | `80–120ms` на элемент, не больше 4 элементов в цепочке |
| Порядок | текстовый блок начинает на `60ms` раньше фото в той же секции |

Секции ниже Hero сейчас не анимированы вообще — это правило распространяется
на все секции (Портфолио, О дизайнере, Услуги, Этапы, Что ценят наши клиенты,
Контакты) и
на карточки внутри Портфолио (по одной, с тем же stagger).

## 3. Hero (кинематографичный, полноэкранный)

Сохранить общую механику текущего Hero (`hero-fade-up`, Ken Burns), но
адаптировать под полноэкранный формат:

- **Вход текста:** та же ступенчатая последовательность, что сейчас
  (`opacity 0→1`, `translateY 18px→0`, `900ms ease-out`), шаг между
  элементами `120–150ms`, начиная с `100ms` после загрузки — не менять,
  уже хорошо откалибровано.
- **Ken Burns фона:** `scale(1) → scale(1.08)`, `24s`, `ease-in-out`,
  `alternate infinite` — оставить как есть, это единственное "дышащее"
  движение на экране, усиливать не нужно.
- **Scroll-индикатор:** заменить `animate-pulse` на менее навязчивое
  движение — вертикальная линия `12px→20px` за `1600ms ease-in-out
  alternate infinite` (более медленный дыхательный ритм вместо мигания).
- Никакого дополнительного parallax-слоя из нескольких плоскостей и никакого
  видео-фона в первой версии — фото + Ken Burns достаточно для
  «кинематографичности» без лишнего веса.

## 4. Переходы между секциями

- Смена фона (светлый ↔ тёмный) происходит одномоментно с границей секции
  (`background-color` не анимируется отдельно — это не плавный градиент, а
  чёткий рез между «сценами», как разворот журнала).
- Длинные паузы (раздел «Отступы» в `design-system.md`) — это единственный
  «эффект перехода»: пустое пространство работает как затемнение между
  сценами вместо анимации.

## 5. Hover-эффекты

| Элемент | Эффект | Длительность | Easing |
|---|---|---|---|
| Фото в карточке портфолио | `scale(1) → scale(1.035–1.05)` | `900–1200ms` | `ease-out` |
| Фото в галерее проекта | `scale(1) → scale(1.03)` | `700ms` | `ease-out` |
| Текстовая ссылка (нав, "Смотреть проект") | `underline` `width 0→100%` слева направо | `250ms` | `ease-out` |
| Кнопка secondary (обводка) | заливка-подложка снизу вверх или слева направо | `300ms` | `ease-out` |
| Заголовок карточки | смена цвета на `accent` | `400–500ms` | `ease` (без transform) |

Курсор-лейбл при наведении на "Смотреть проект" (как в YSG/Holloway Li) —
**опционально, фаза 2**, не входит в первую реализацию: усложняет доступность
курсора и не критична для цели «фотография — главный герой».

## 6. Лёгкий параллакс

Только два места, оба — фон, не контент:

1. **Фон Hero** — уже описан выше (Ken Burns), это и есть единственное
   движение фона Hero, дополнительный scroll-parallax поверх него не
   добавляется (не накладывать два движения на один слой).
2. **Обложка открытого проекта** (`ProjectDetail`, блок `aspect-[21/9]`) —
   фон двигается на `10–15%` медленнее скролла контента:
   `transform: translateY(scrollDelta * 0.12)`, считать через
   `requestAnimationFrame` + `IntersectionObserver` (не на каждый scroll-event
   без rAF-троттлинга), ограничить диапазон смещения `±40px`, чтобы фото не
   уезжало за пределы контейнера.

Никакого параллакса на текстовые блоки, карточки или иконки — только два
фото выше.

## 7. Галерея проекта (редакционная раскладка)

> **Для первого прототипа:** механика открытия проекта (текущая модалка
> `ProjectDetail`, без отдельного маршрута) не меняется — ниже описана
> только анимация содержимого *внутри* неё. Существующий вход/выход модалки,
> `Escape`, focus trap и возврат фокуса остаются как есть.

- Раскладка чередуется (крупное full-bleed фото → пара средних → крупное),
  см. `design-system.md` §8.
- Каждое фото/группа появляется через тот же reveal-on-scroll (раздел 2),
  но с более коротким stagger (`60ms`) между фото внутри одной "пары".
- Смена фото в потенциальном будущем полноэкранном просмотре (если появится
  лайтбокс) — `opacity`-кроссфейд `300ms`, без слайд-транзиций и без свайп-
  инерции с "отскоком".

## 8. `prefers-reduced-motion: reduce`

Обязательный блок в `index.css`, применяется глобально:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Плюс точечные замены (не просто "выключить всё", а осмысленная деградация):

- **Ken Burns** — отключается полностью, фон статичен на `scale(1)`.
- **Reveal-on-scroll** — вместо `translateY` + `opacity` остаётся только
  мгновенное `opacity: 1` (контент виден сразу, без задержки/сдвига).
- **Параллакс обложки проекта** — отключается, фон статичен.
- **Scroll-индикатор Hero** — без дыхательной анимации, статичная линия.
- Hover-эффекты (underline, scale фото) можно оставить — это не системная
  анимация экрана, а реакция на явное действие пользователя (наведение), не
  триггерит вестибулярные проблемы так, как автономные движения экрана.

## 9. Технические заметки для реализации

- Один переиспользуемый хук/утилита на `IntersectionObserver` для всех
  reveal-эффектов (секции, карточки, фото галереи) — не плодить разные
  реализации по компонентам.
- `will-change: transform` — только на элементе в момент активной анимации
  (добавлять/убирать классом), не держать постоянно на статичных элементах.
- Проверить итоговый список анимаций через DevTools Performance на слабом
  устройстве (throttling 4x CPU) перед сдачей — цель: не проседать ниже
  50fps на скролле.
